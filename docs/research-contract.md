# Local research execution contract

This document specifies interfaces and commands. Experiment results remain in
JSON/CSV and figures; no research report is generated by these commands.

## Data and calendar

`scripts/recover_research_data.py` authenticates with the local `.env`, requests
quotation data only, stages returned rows, and applies only quality-qualified
days with backups. It never interpolates missing bars. A second direct query
of a missing interval distinguishes page boundaries from unavailable data.

`scripts/normalize_raw_partitions.py` removes cross-file duplicate timestamps
and places observations in their actual timestamp month. It checks that the
canonical observations used by the existing loader remain identical.

`scripts/prepare_extended_study.py` uses the pinned XKRX calendar and explicitly
sourced 2026 closures. Its candidate audit retains failed recent windows.
Historical windows are chosen by data availability, with at least 95% coverage
for every symbol and split, before any return is evaluated. These historical
data have been reused; they are not a prospective holdout.

Synchronous missing prints may be marketwide halts. The 55 symbol-days that
remain sparse after direct KIS requery are not proven provider failures. The
qualified-window filter can exclude stressed regimes. `scripts/stress_gap_audit.py`
therefore evaluates frozen policies separately on observed bars, with no price
interpolation and exact execution timestamps. Some windows overlap training
history; this is an exploratory stress audit, not another out-of-sample test.
Halt classification remains incomplete. The feature manifest pins all parquet
hashes, and each audit pins the pre-test frozen model and normalization manifest.

## Actions, execution and observations

- The research action schema is `target-weight-6`: `[0,.2,.4,.6,.8,1]`.
- Target equity is `cash + shares * observed Close`. Quantities use observable
  Close and integer floor division. Execution may reduce buys for price/cost
  gaps; a future discount cannot increase the planned quantity.
- Missing execution prices produce no fill or cost. Fees, dynamic spread,
  slippage and date-dependent sell tax are recorded separately from reward
  penalties. Cost basis uses proportional average cost and excludes fees.
- Features are normalized using training data only. A 12-bar intraday window
  resets across days and gaps, with zero padding and explicit validity bits.
  The controlled contract has 157 values: 132 market values, 12 validity bits
  and 13 account/context values.
- Closing uses the final observed mark plus modeled sell friction. It is an
  offline settlement approximation. Reward recognizes liquidation-value
  equity, including the observable exit-cost reserve, without double charging
  at actual settlement.

## Multi-day risk experiment

Conditions I/J/K share 12-bar input, a 5-percentage-point rebalance tolerance,
up to 6 underlying bars per decision, and a 20-session training horizon.
Positions settle to cash daily; no new position opens across a session
boundary. The liquidation-equity peak persists across all days of the episode.

- I: no additional risk penalty.
- J: fixed multiplier 0.1.
- K: projected dual updates, initial multiplier 0.1, learning rate 10, cap 10.

Risk cost is `max(episode drawdown - .05, 0)`. The budget is mean cost `.001`,
not a hard 5% maximum drawdown guarantee. These experiments use per-bar gamma
1 and GAE lambda .95. Macro rewards and bootstrapping use actual durations;
GAE uses `(gamma * lambda) ** elapsed_bars`. The critic predicts penalized
return; this is a single-critic PPO-Lagrangian surrogate, not CPO.

Examples from the workspace root:

```bash
./market.sh python scripts/prepare_extended_study.py --output runs/NEW/plan.json
./market.sh ablation --output runs/NEW/study --conditions I,J,K --seeds 42,43,44 \
  --folds 3 --validation-days 60 --test-days 20 --fold-plan runs/NEW/plan.json \
  --bar-budget 200000 --timesteps 200000 --gamma 1 --gae-lambda .95 \
  --ent-coef .5 --episode-days 20 --drawdown-threshold .05 --risk-budget .001
./market.sh python experiments/finalize_research.py runs/NEW/study
```

Use a new output directory for a new protocol. Validation determines the
checkpoint and comparison condition before test evaluation. If no condition
meets every validation risk budget, the selected artifact remains explicitly
a research comparator. Earlier fold tests can overlap later validation.

## Predictive and policy diagnostics

`experiments/predictive_diagnostics.py` fits Ridge and histogram gradient
boosting on training data, with fixed hyperparameters and no random temporal
early-stopping split. Inputs contain current/past features only. Labels use
future observed exit Close relative to the next-minute entry execution, and
never cross sessions or gaps. Cost-aware events use a predeclared observable
cost gate; event means are not compounded portfolio returns.

`scripts/diagnose_research_policies.py` reconstructs the exact initial network,
checks its validation metrics against checkpoint zero, measures reliance on
market/account inputs, and audits value predictions against deterministic
validation Monte Carlo returns. Permutation reliance is not causal predictive
value; constant fields are marked unidentifiable. Stochastic training value
metrics are exported separately from this deterministic critic audit.

## Java/Python research replay

```bash
./market.sh research-serve --bundle runs/STUDY/fold_03/K/seed_42 --symbol 005930
./market.sh gradle researchDryRun --args='--url http://127.0.0.1:8766 --output /tmp/NEW-java-replay --restart-at 25'
```

The standalone Java CLI never creates a Spring application or broker client.
`research-dry-run-v1` has `/metadata`, `/reset`, `/state` and `/step` endpoints
on loopback. Every step supplies session/model identifiers, decision sequence,
cash, integer shares and cost basis. Stale or mismatched state is rejected
before inference. Java independently plans quantities and applies the ordered
target-fill and settlement events, then verifies the Python state. Snapshot
restoration is checked during replay; `--resume PATH` resumes the Java client
against an unchanged server session. Broker orders are always disabled.

These research artifacts do not use the legacy unit-action serving contract.

Java restart comparisons use the same small arithmetic tolerance as stepwise
accounting. Session, artifact, decision count and integer holdings still must
match exactly. Resume requires that the Python process/session remains alive;
the Java snapshot does not persist the Python environment across server restarts.

## Prospective evaluation gate

`scripts/future_research_holdout.py` seals all three conditions and seeds before
the future window starts, using the pre-test historical selection. The reserved
window is 2026-11-10 through 2026-12-07. Evaluation requires the following day,
at least 95% coverage per symbol, and the final observed session. Partial scores
are not exposed. Code, evaluator, model, normalization and historical-prefix
integrity checks precede scoring. No model fitting or reselection is allowed.

```bash
./market.sh future-check --output runs/completion-v3/future-holdout
```

The exact sealed runtime and evaluator were copied to `runs/completion-v3/frozen-runtime`.
To evaluate after subsequent source changes, use:

```bash
./market.sh python runs/completion-v3/frozen-runtime/scripts/future_research_holdout.py \
  --output runs/completion-v3/future-holdout
```

This is a manual gate, not an installed collection scheduler. It requires the
future raw observations to have been collected before evaluation.

## Result assets without a report

```bash
./market.sh python scripts/package_research_results.py \
  --root runs/completion-v3 --output runs/NEW/result-assets
```

The exporter validates completed shards and writes flat CSV tables, descriptive
paired seed differences, PNG/SVG figures and source checksums. It performs no
training or reselection. Stocks are averaged within seed first; three optimizer
seeds, correlated stocks and overlapping temporal windows must not be presented
as independent evidence of statistical significance. The stress shading is a
seed range. Cost addback is accounting, not a no-cost policy counterfactual.
